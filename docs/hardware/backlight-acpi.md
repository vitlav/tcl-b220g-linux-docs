# Подсветка через ACPI: SPMI и PM6150L PWM

Состояние на 25 сентября 2026 года. **Аппаратно подтверждено:** изменение
скважности PMIC PWM меняет яркость встроенной панели. Пользователь подтвердил
монотонное увеличение яркости и оба крайних значения: raw `0` — максимальная
яркость, raw `511` — визуально полная темнота. Это проверка на ALT Linux,
ACPI, ядре `7.2.4-tcl-acpi-public70+` с дополнением PWM software-node lookup.
Проверка через DT не проводилась.

Постоянный драйвер подсветки и `/sys/class/backlight` на основании этих
результатов ещё не установлены. Полное выключение питания панели, cold-start
моста и suspend/resume этим тестом не подтверждаются.

## Контроллер SPMI

ACPI обозначает контроллер как `QCOM080C`, PMIC — `QCOM0830` (PM01).
Проверена временная регистрация контроллера, чтение PMIC через regmap,
создание PWM provider и consumer, затем освобождение устройств и IRQ.

| Ресурс | Адрес | Размер |
|---|---:|---:|
| core | `0x0c440000` | `0x1100` |
| chnls | `0x0c600000` | `0x2000000` |
| obsrvr | `0x0e600000` | `0x100000` |
| intr | `0x0e700000` | `0xa0000` |
| cnfg | `0x0c40a000` | `0x26000` |
| PDC | `0x0b220000` | `0x30000` |

PMIC arbiter — v5, version `0x50000000`. Чтение observer работает через EE0.
Родительский IRQ — GIC INTID513 (SPI481), level-high; номер Linux IRQ не
является частью аппаратной спецификации. Используется PDC pin1.
Проверены регистрация и удаление обработчика; доставка реального прерывания
от PMIC-периферии отдельно ещё не испытана.

## Активный источник PWM

| Параметр | Проверенное значение |
|---|---|
| PMIC / SPMI SID | PM6150L, SID5 для LPG/WLED |
| Активный PWM | base `0xbc00`, APID207, subtype `0x0b` |
| Владелец записи / IRQ | EE0 / EE0 |
| Индекс в таблице LPG драйвера | 3 (нумерация с нуля) |
| Источник / разрешение | 19,2 МГц / 9 бит |
| Predivider / exponent | 1 / 5 |
| Регистры `0xbc40..0xbc46` в исходном состоянии | `00 07 05 00 00 01 80` |
| Исходная скважность | raw256, output enabled |
| `pwm_get_state_hw()` | period851667 ns, duty426667 ns, normal polarity |
| Расчёт полного аппаратного периода | 512 × 32 / 19200000 ≈ 853333 ns, 1171,875 Гц |
| Установка raw duty | `0xbc44..0xbc45`, затем sync `0xbc47 = 1` |

Разница между периодом из Linux readback и полным 512-тактовым периодом
отражает используемый драйвером расчёт; это не измерение осциллографом.
LPG `0xb100`, `0xb200`, `0xb300` и PWM `0xbd00` имели отключённый выход.
WLED `0xd800`/`0xd900` присутствует, но enable-регистры `0xd846` и `0xd946`
равны нулю. Наличие WLED не означает, что именно он управляет этой панелью.

GPIO6 PM6150L (SID4, `0xc500`, APID195) настроен как выход: регистры
`0xc540..0xc546 = 01 00 04 00 82 03 80`, function1/source2 с инверсией,
VIN0, pull-down, CMOS, high drive, enabled. Это согласуется с обратной
шкалой яркости, но физическая связь GPIO6 с панелью отдельно не доказана.
Настройки GPIO и TLMM GPIO21 в проверках не менялись.

## Проверки и границы результата

Проверены десять последовательных значений raw от511 до0, обратный проход
0→128→256→383→511, крайние значения и уровни450/500/510. После каждой записи
считывались регистры; после каждого цикла восстанавливался raw256 и
проверялось совпадение всех семи конфигурационных байтов. Временные модули
удалялись, состояние PDC восстанавливалось. Частота, питание и GPIO при
изменении яркости не перепрограммировались.

LPG provider и software-node consumer успешно связаны через `pwm_get()`;
прочитано аппаратное состояние канала3. Это проверка получения PWM, а не
доказательство готовности постоянного драйвера `pwm-backlight`.

## Требования к постоянной реализации

1. Сохранить единственного владельца SPMI/PDC, корректный probe/remove и
   освобождение IRQ; не регистрировать параллельного владельца ресурсов.
2. Представить PMIC/LPG и связи PWM через firmware nodes; при PWM-only probe
   не менять настройки tri-LED, унаследованные от firmware.
3. Согласовать полярность с GPIO и семантикой выключения. Кандидат для шкалы
   brightness0..511 — `raw = 511 - brightness`; это отображение крайних
   значений, а не измеренная кривая воспринимаемой яркости.
4. Учесть, что текущий LPG принимает только `PWM_POLARITY_NORMAL`.
   Обычный duty0 или disable при существующей инверсии не означает тёмную
   панель. Поэтому прямое подключение обычного `pwm-backlight` пока неверно.
5. Проверить brightness0, blank/unblank, shutdown/remove и восстановление
   после сна, затем предоставить стандартный интерфейс backlight пользователю.

## Сон

В проверенном ядре доступны `freeze mem disk`, а `/sys/power/mem_sleep`
содержит только `[s2idle]`. `deep` не предлагается, `/sys/power/pm_test`
отсутствует; зарегистрированных RTC для автоматического пробуждения не
обнаружено. Это проверка доступных интерфейсов, **не успешный suspend/resume**.
Проверка сна и возврата экрана, ввода, сети и звука остаётся отдельной задачей.
