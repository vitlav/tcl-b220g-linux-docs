# Модем и GNSS: MPSS firmware и память

Windows inventory содержит Snapdragon X15 LTE и Qualcomm Location (QCOM0872). Это подтверждение описания устройств Windows, а не проверенный LTE-сеанс или GNSS fix в Linux. В доступном описании TCL указан Nano SIM + TF; физическая работа SIM-интерфейса в Linux не проверена.

**Подтверждено для Linux:** MPSS работает с OEM NM firmware и обеспечивает проверенный [Wi-Fi](wifi.md). QMI LOC/PDS в проверенных QRTR-снимках не объявлены. GNSS fix, антенна и передача данных LTE не проверены. Задача: [19500](https://bugs.etersoft.ru/19500).

## Варианты OEM firmware

| Параметр | NM, используемый с Wi-Fi | Полный MSM, кандидат для GNSS |
|---|---|---|
| Файл | qcmpss7180_nm.mbn | qcmpss7180.mbn |
| Размер файла | 5057288 байт | 61815992 байт |
| Идентификатор | rennell.gennm.prodQ | rennell.gen.prodQ |
| Область PT_LOAD | 0x86000000–0x88000000, конец исключён | 0x86000000–0x8e400000, конец исключён |
| Требуемый резерв | 32 MiB | 132 MiB |
| Строки QMI_LOC/gps/gps_service | При поиске не найдены | Найдены |
| Аппаратная проверка | MPSS/WLAN работают | Загрузка полного варианта в рамках этих результатов не подтверждена |

Для Windows Hardware ID `ACPI VEN_QCOM DEV_081E SUBSYS_CLS07180` OEM INF выбирает `SUBSYS_Device_AMSS_MSM_Ext → SUBSYSReg_AMSS_MSM`, где указан полный файл qcmpss7180.mbn.

Совокупность INF, различий образов и отсутствия LOC/PDS делает полный вариант обоснованным кандидатом. Поиск строк не доказывает ни отсутствие кода в NM, ни работоспособность GNSS в полной firmware.

## Карта памяти

| Область | Диапазон, конец исключён | Отношение к полному MPSS |
|---|---|---|
| Venus | 0x85b00000–0x86000000 | Не пересекается |
| Полный MPSS | 0x86000000–0x8e400000 | 132 MiB |
| Унаследованный ipa_fw_mem | 0x8b700000–0x8b710000 | Находится внутри полного MPSS |
| ADSP | 0x90b00000–0x93300000 | Не пересекается |
| WLAN MSA | 0x93900000–0x93b00000 | Не пересекается |

Полный диапазон помещается в исследованный OEM reserved region ниже первой SystemRAM 0x94600000. В проверенном DT IPA@1e40000 отключён, не имеет memory-region; у отдельного memory@8b700000 нет phandle. Это не устанавливает назначение IPA firmware для будущего LTE.

Полный MPSS нельзя подставить в конфигурацию с резервом 32 MiB. Для новой конфигурации требуется согласовать 132 MiB с остальной картой памяти; вложенный отдельный резерв IPA должен быть явно учтён. Включение IPA и LTE требует собственного анализа, а не только изменения firmware-name.

## Интерфейс GNSS и критерии проверки

Предполагаемый путь — сервис QMI LOC/PDS через QRTR. Наличие отдельного стандартного Linux GNSS/NMEA-устройства пока не установлено; имя Location в Windows не определяет Linux API автоматически.

Последовательность проверки полного варианта:

1. Подтверждение карты памяти, успешной загрузки и аутентификации firmware через remoteproc/SCM.
2. Проверка QRTR-сервисов и ответов QMI LOC/PDS, если они появились.
3. Проверка standalone GNSS, получения fix и состояния антенны.
4. Отдельное подтверждение сохранности WLAN и других функций MPSS.

Появление сервиса ещё не означает fix. Подстановка тестовых координат проверяла бы только клиентское ПО, а не приём спутникового сигнала. Перезапуск MPSS затрагивает Wi-Fi, поэтому для эксперимента необходим независимый способ доступа или заранее проверенное сохранение диагностики.

Координаты и индивидуальные modem storage не входят в публичную спецификацию. Рабочая NM-конфигурация и сведения Windows не позволяют объявить GNSS или LTE готовыми.
