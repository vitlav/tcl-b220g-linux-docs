# Аппаратное видео: Qualcomm Venus

**Проверено на оборудовании:** Venus инициализирован, H.264 декодируется через stateful V4L2 mem2mem. Полноэкранное воспроизведение подтверждено визуально. Корректность всех режимов и стабильность аппаратного пути mpv не подтверждены; известны ошибки, описанные ниже.

Venus выполняет декодирование/кодирование, Adreno — рендеринг и GPU-вывод, DPU — scanout. Работа одного блока не подтверждает использование остальных приложением. [Дисплей и GPU](display.md).

## Ресурсы и зависимости

| Ресурс | Значение |
|---|---|
| Compatible | qcom,sc7180-venus |
| MMIO | 0xaa00000 / 0xff000 |
| IRQ | GIC SPI174 level-high, INTID206 |
| IOMMU | Apps SMMU 0x15000000, specifier 0xc00,0x60 |
| Reserved memory | 0x85b00000 / 0x500000 (5 MiB) |
| Clocks | VIDEOCC 0xab00000: core6, iface3, bus5, vcodec0_core2, vcodec0_bus1 |
| Power domains | VIDEOCC venus0/vcodec0_1; RPMh CX0 |
| Interconnect | video-mem и cpu-cfg; полные ячейки в DT |
| Драйвер | CONFIG_VIDEO_QCOM_VENUS; HFI4XX, VPU AR50 по коду |
| Firmware path | qcom/venus-5.4/venus.mbn |
| Проверенная firmware | VIDEO.VE.5.4-00064-PROD-1 |

[Полный реестр DT](full-inventory.md) содержит OPP и поставщиков ресурсов. Включённый узел DT не гарантирует привязку драйвера в каждом образе. Для работы нужны VIDEOCC, power domains, SCM/PAS, firmware, IOMMU и reserved memory.

В проверенной конфигурации ядра `6.18.34-tcl-ice1` зарегистрированы decoder и encoder. Номера `/dev/videoN` динамические; выбирать устройства по имени и V4L2 capabilities. Наличие encoder-узла не подтверждает аппаратное кодирование.

## Матрица кодеков

| Формат / интерфейс | Подтверждение |
|---|---|
| H.264 | Декодирование и вывод проверены, с ограничениями подачи данных |
| VP8, VP9, HEVC, MPEG2 | Перечислены runtime decoder; отдельные тесты не выполнены |
| Профили, 10-bit, 4K, максимальные FPS | Полная матрица не установлена |
| AV1 | В изученной таблице Venus decoder отсутствует; наличие программного decoder не доказывает аппаратную поддержку |
| VA-API / Vulkan Video | Работа на TCL не подтверждена |
| Encoder | Узел зарегистрирован; кодирование не проверено |

Wrapper `h264_v4l2m2m` в списке FFmpeg не является доказательством доступного оборудования. Лог реального запуска должен подтверждать Qualcomm Venus и выбранный decoder.

## Проверка корректности H.264

FFmpeg 8.0.1, H.264 High 1920×1080 30 fps, 300 кадров:

| Путь | Кадры / результат | CPU time user+system |
|---|---|---:|
| Software h264, threads2, -xerror | 300/300, exit0, без decode errors | 3.756 s |
| h264_v4l2m2m, без ограничения подачи | Corrupt decoded frame около кадра21, exit183 | Не успешный benchmark |
| h264_v4l2m2m, подача -re, -xerror | 300/300, exit0, без decode errors | 0.224 s |

Elapsed software 1.869 s и аппаратного запуска с -re 9.516 s нельзя сравнивать как максимальную скорость декодеров: во втором случае подача ограничена реальным временем. Отдельный аппаратный Baseline 720p запуск завершился exit0, но выдал лишь 68/90 кадров — тест не пройден.

Успешная команда, где `input.mp4` — подготовленный тестовый файл:

```sh
ffmpeg -hide_banner -nostdin -xerror -benchmark -re -c:v h264_v4l2m2m -i input.mp4 -an -f null -
```

Реальная подача -re устранила наблюдаемую ошибку в этом тесте; это обход условия воспроизведения, не доказанное исправление. Гипотеза связана с обработкой enqueue EAGAIN/G_FMT в FFmpeg, но фактическая причинная последовательность ioctl не установлена. Побитовое сравнение декодированных кадров с software не выполнено.

## CPU при экранном воспроизведении

Big Buck Bunny, H.264 Main 1920×1080 24 fps, полный экран Weston GL, без звука. FFplay: одинаковый файл, старт с 60 s, 5 s прогрева, 25 s измерения, порядок hardware → software → hardware. Частоты CPU/GPU не фиксированы.

| Режим | Плеер, % одного CPU | Weston, % одного CPU | Система, % восьми CPU |
|---|---:|---:|---:|
| Аппаратный 1 | 157.2 | 6.2 | 21.5 |
| Программный | 78.7 | 7.4 | 12.1 |
| Аппаратный 2 | 154.0 | 6.1 | 21.1 |

В этом ffplay аппаратный путь требует примерно вдвое больше CPU плеера. Причина затрат не установлена; низкая стоимость decode-to-null не описывает копирование, преобразование и вывод кадров. Энергопотребление этим измерением не определялось.

Пользователь подтвердил хорошее изображение аппаратного ffplay. В измеренных окнах corrupt/decode errors отсутствовали, после прогрева drops не росли; стартовые потери были. Это не доказательство отсутствия любых редких сбоев.

## mpv

Проверена версия 0.41.0: аппаратный путь Venus `v4l2m2m-copy`, вывод gpu-next/OpenGL/Wayland на FD618. Предварительно CPU плеера 49.7%, software 86.8% одного ядра, но окна не покадрово идентичны и A/B/A не завершён. Эти цифры не являются сопоставимым итоговым benchmark.

Наблюдались зависание при завершении со spin в zero-timeout ppoll(POLLOUT) на V4L2 decoder, стартовые артефакты и менее плавное движение. Частые G_FMT в журнале — наблюдение, а не доказанная причина повреждения кадров.

При `--hwdec=no` с тем же GPU-выводом пользователь подтвердил более плавное изображение без искажений. Таким образом, аппаратный вывод через Adreno работает и при программном декодировании; весь аппаратный путь mpv пока нельзя считать исправным.

## Дальнейшая проверка

Нужны полный набор кадров с проверкой содержимого, локализация EAGAIN/G_FMT и завершения V4L2, повторяемое сравнение одинаковых сцен, оценка копирования/преобразования форматов и проверка остальных codecs/profiles. Наличие DMABUF/zero-copy или аппаратного decode в браузере не подтверждено этими результатами.
