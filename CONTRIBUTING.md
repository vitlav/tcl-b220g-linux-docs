# Как обновлять документацию

1. Указывать дату, точный kernel/Image hash, DT и boot ID для аппаратных результатов.
2. Различать описание DT, Windows/ACPI, симуляцию AML, успешную сборку и реальный аппаратный тест.
3. Обновлять docs/status.md после подтверждённого изменения; подробности писать в тематический отчёт. Не переписывать старые неудачи как успешные.
4. Добавлять артефактам SHA256 и происхождение. Не публиковать пароли, ключи, координаты GNSS, MSDM payload или полный личный образ диска.
5. Не запускать исторические скрипты без проверки адресов, целевых устройств и версии ядра. Перезагрузку согласовывать; заранее проверять фактическую запись диагностики на USB и резервный доступ.
6. Имена коммитов — на английском. Для публикации в этой инфраструктуре использовать gpush и remote pub.*, если такой remote настроен.

Исходники Linux и сторонних проектов сохраняют свои заголовки и лицензии. Единая лицензия на всю коллекцию намеренно не назначена: материалы имеют разное происхождение.
