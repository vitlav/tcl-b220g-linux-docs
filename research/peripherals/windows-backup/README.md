## Проверка завершения

`COMPLETE` создаётся только после проверки SHA256 полного извлечённого потока всех шести LUN и успешного `borg check --repository-only`. Один лишь файл lunN-create.json не означает завершения проверки. Источник и приёмник независимо считали SHA256; отчёты находятся в logs/lunN-received.json. Результаты обратного чтения — logs/lunN-verified.json.

## Извлечение для восстановления

Установить Borg 1.x средствами epm. Использовать каталог с достаточным свободным местом: для lun0.img требуется как минимум 251331084288 байт. Не извлекать на FAT32. Пример извлекает обычный файл, не пишет на устройство:

```bash
export BORG_BASE_DIR=/tmp/tcl-borg-restore-state
repo=/var/ftp/tmp/lav/tcl/windows-ufs-20260908/repository
borg list "$repo"
# Перейти в подготовленный пустой каталог на большом диске.
borg extract "$repo::windows-20260908-lun0" lun0.img
sha256sum lun0.img
```

Сверить размер и SHA256 с logs/lun0-received.json; аналогично для остальных LUN. Можно проверять без выделения места под raw-образ:

```bash
set -o pipefail
borg extract --stdout "$repo::windows-20260908-lun0" lun0.img | sha256sum
```

Для переноса архива сохранить весь repository, logs, archives.json и COMPLETE. Каталог BORG_BASE_DIR содержит локальное состояние/кэш, не является самим архивом.

Фактическую запись обратно пока не проводили. Перед ней нужна отдельная загрузочная система и проверка каждого целевого LUN: восстановление служебных LUN способно изменить загрузочную цепочку. Проверенная извлекаемость архива не равна испытанному восстановлению с последующей загрузкой Windows.
