# Задание упаковщику: ядро Armbian UEFI ARM64 для TCL B220G

Дата: 2026-09-08. Объект: TCL B220G, Qualcomm SC7180, Ubuntu ARM64.
Это подготовительное задание: сборка, установка, публикация и команды на TCL не выполнялись.

## Применимость alt-packaging-agents

Прочитаны `/srv/lav/Projects/Claude/alt-packaging-agents/.claude/agents/build.md`,
`CLAUDE.md`, `config.md`, `docs/commands.md`, `docs/gear-rules.md`,
`docs/spec-format.md`, `docs/changelog.md`, `docs/workflow-new-package.md`,
`docs/common-mistakes.md`, `docs/rules.md`.

Этот workflow предназначен для ALT RPM: spec, gear, rpmbb, hasher, girar.
Настроенный hasher — Sisyphus x86_64, без сети. Он не является готовой средой
сборки Armbian DEB ARM64. Передача задачи упаковщику выполнена, но создание ALT
spec и конвертация RPM через alien не решат задачу ядра Ubuntu. Для этой задачи
нужен отдельный upstream Armbian workflow; неподходящие шаги публикации в girar
применять не следует.

ядра; потребность зависит от реально выбранного build workflow.

## Порядок выполнения

1. Зафиксировать commit `armbian/build`, фактическую ветку ядра, версию исходников
   и полный набор патчей UEFI ARM64. Не выбирать по слову current: сравнить версии
   с работающим 6.18.34-stb-qc7+. Само слово Armbian не означает более новое ядро.
2. Сначала исследовать официальные готовые DEB семейства UEFI ARM64. Получить
   image/modules и DTB-пакеты одной версии; headers нужны для внешнего модуля,
   но не для загрузки. Точные имена определяются по текущему репозиторию.
3. Проверить SHA256 по подписанному индексу репозитория либо другому официальному
   механизму проверки. Сохранить URL, дату, версию, архитектуру и происхождение.
4. Распаковать для анализа без установки: `dpkg-deb --info` и `dpkg-deb --contents`,
   control-скрипты, config, Image, modules. Сравнить обязательные опции с рабочим
   ядром и модули с действующим initramfs. Проверить Architecture: arm64 и отсутствие
   ошибочных host-arch зависимостей. Скрипты postinst/prerm не исполнять при анализе.
5. Если готового подходящего пакета нет, собрать только ядро штатным Armbian build
   в поддерживаемом upstream контейнере/хосте. Точная команда compile.sh зависит
   от закреплённой версии и должна быть взята из её README/CLI, а не перенесена из
   старых инструкций. Параметры задания: UEFI ARM64 board/family, выбранная branch,
   kernel-only, неизменяемый config fragment и отдельная версия пакета.
6. Пакеты инструментов на builder устанавливать через epm. Не запускать общую
   подготовку Debian-хоста Armbian прямо на ALT. Проверить требования контейнера,
   доступ к Docker daemon, ресурсы и потребность в привилегиях до запуска.
7. Отдельно подготовить DTB и initramfs под точный `uname -r` нового ядра.
   Не копировать старые .ko: vermagic/ABI должны соответствовать новому ядру.
8. Сначала передать артефакты и отчёт администратору. Установка и перезагрузка —
   следующий отдельный этап после проверки пакетов и плана возврата.

## Обязательные условия совместимости

- Сохранить проверенный DTS TCL и зарезервированные GPIO58–62; не заменять DTS
  generic Qualcomm/другой панели. DTS проверяется по bindings выбранного ядра.
- Нужны действующие цепочки UFS, Qualcomm clocks/interconnect/regulators/pinctrl,
  remoteproc, QRTR, RMTFS, Wi-Fi и USB. Проверяется весь набор транзитивных модулей.
- Проверить поддержку loop+Btrfs и FAT/USB в initramfs: текущий корень — образ
  rootfs.img на USB, а не установленная система на внутреннем UFS.
- Сохранить файлы firmware и существующий порядок запуска RMTFS/Wi-Fi/DHCP/SSH.
  Приватные конфигурации Wi-Fi, ключи SSH и содержимое UFS не включать в публикацию.
- Первый тест новой базы сохраняет существующий EFI-вывод. Само обновление ядра
  не добавляет драйвер LT8911EXB и не гарантирует native DRM/Wayland.
- Нельзя включать случайный драйвер LT8911EXB до сверки API DRM, питания и OEM
  последовательности. Это отдельная задача драйвера после работоспособной базы.
- Внутренние UFS LUN остаются read-only; рабочее ядро, initramfs и GRUB-пункт
  сохраняются. Установка пакета не должна незаметно перезаписать рабочую загрузку.

## Что передать по результату

- DEB ARM64, SHA256, список файлов и maintainer scripts.
- Kernel config, полный config diff, DTB/DTS diff и результаты проверки bindings.
- Версии источников, commit build, список патчей, точную команду и полный build log.
- Image, modules одной версии, initramfs manifest и список требуемых firmware.
- Список непокрытых устройств и параметры безопасного тестового пункта GRUB.
- Отдельно указать: компиляция/упаковка успешны либо нет; загрузка на TCL ещё не
  проверена. Не называть сборку рабочей по одному успешному compile.

Текущая оценка: самый короткий путь — проверить официальный готовый Armbian DEB;
если конфигурация не подходит, подготовить воспроизводимую kernel-only сборку.
ALT RPM workflow не следует превращать в промежуточный формат для Ubuntu.

## Обязательная коррекция после аппаратного теста

Готовый7.1.8-edge-arm64 непригоден для текущего TCL DT: CONFIG_NVMEM_QCOM_QFPROM выключен, USB2 PHY deferred на efuse@784000/hstx-trim-primary@25b, USB deferred на PHY. Включить QFPROM (предпочтительно=y для раннего boot), проверить его зависимости. Учесть CONFIG_HWSPINLOCK_QCOM и QCOM_APCS_IPC (=y либо явная ранняя загрузка). Проверить все активные DT suppliers, а не только modules.dep. Не удалять nvmem calibration references. QMP combo orientation/data-lanes/DRM bridge error требует отдельной проверки bindings.
