Это выявленные по чтению риски, не воспроизведённые сбои на TCL. Более раннюю оценку «стандартные API, вероятно переносим» уточнить: регистровая часть полезна, glue/lifecycle требует переработки. Ошибки I2C/regmap в длинных последовательностях также требуют аудита; не считать таблицы доказанно пригодными по совпадению ID.

## Рекомендуемая архитектура задания

I2C LT8911EXB как DRM bridge с подключением к MIPI DSI host и выходной eDP panel; стандартный двусторонний OF graph, без /lcds и force-attached. Это проектное решение, binding пока не реализован и не проверен. Не выдавать придуманную DTS compatible за upstream binding. Допустимость panel-wrapper как промежуточного решения отдельно оценить по MSM6.18, не копировать нынешний SpacemiT glue.

Подтверждённые входные данные TCL: I2C10(a90000),7bit0x29,100kHz; ID17 05 E0;4DSI lanes RGB888;1920x1080, pixelclock142.52MHz из EDID, H58/42/60,V3/5/54;2eDP lanes,2.7Gbps по status bridge. OEM GPIO23/20/51/26/13/21 и задержки описаны graphics-research; функции отдельных линий не считать доказанными по GPIO номеру. Не смешивать Windows и UEFI reset sequences.

Первый аппаратный этап после готовности драйвера: один фиксированный EDID режим, GPU/GMU остаются выключены, проверить KMS scanout. Wayland/pixman возможен после рабочего KMS; аппаратное ускорение Adreno — отдельный этап. Поддержка KMS на6.18 уже есть, переход версии не является обязательным условием.
