## AW96105: настройки TCL извлечены из ACPI

Из SAR1._DSM (function 2) извлечён OEM-блок 892 байта. Проверены сумма байтов после заголовка (0x7139), строка AW96105, длина данных 832 байта, 138 пар register16/value32 и точное окончание блока. Формат соответствует парсеру drivers/iio/proximity/aw96103.c в исследуемом Linux 6.18.34. Сохранён как aw96103_0.bin — именно это имя запрашивает драйвер даже для AW96105. Это конфигурация регистров, не исполняемый код микроконтроллера.

SHA256: 7a7be16421d74b963a73bc7a4c0c16fae90af4fb306c49762ad612acdbe526f4.

SCANCTRL0=0x1f1f: младшая маска включает пять каналов. IRQEN=0x206. Это не доказывает наличие пяти физических электродов.

Важное соответствие: ACPI I2C5 имеет MMIO 0x890000, то есть в текущем Linux это i2c-4, а не i2c-5. Подтверждено по sysfs живой системы. На шине уже зарегистрированы 4-0005 и 4-002c. Датчик ожидается по адресу 0x12; GPIO34, ACPI Edge/ActiveBoth/PullUp. Сканирование и записи в датчик не выполнялись.

Драйвер уже предоставляет IIO и пять каналов AW96105 через OF/I2C matching; ACPI match AWDZ9610X отсутствует. Для подключения остаётся установить питание vcc и проверить IRQ/pinctrl, затем контролируемо зарегистрировать устройство. Не подставлять фиктивное питание без выяснения проводки.

Важная особенность кода: при полном отсутствии firmware callback сразу возвращает No firmware, не переходя к встроенной конфигурации. Поэтому наличие драйвера и IIO-узла само по себе не доказывает, что измерения запущены. OEM-блок устраняет неизвестность формата конфигурации, но его применение ещё не проверено на оборудовании.

Артефакты: .claude/docs/tcl-b220g-data/peripherals/sensors/{aw96103_0.bin,registers.tsv,firmware-validation.json}. Требование пользователя: пользоваться стандартными подсистемами ядра даже при собственном аппаратном драйвере.

## Живой запуск через IIO, 2026-09-09

Ядро 6.18.34-tcl-audio2. До подключения CHIPID=0xa9610b00, FWVER2=0x20000000, SCANCTRL0=0, IRQEN=0xfff, DIFF0..4=0 в трёх выборках. Датчик физически отвечает; питание присутствует, измерения выключены.

Собран неизменённый aw96103.c из текущего дерева Linux как внешний модуль; W=1 без предупреждений. Временный tcl_sar_client регистрирует i2c-4/0x12, проверяя compatible платы и OF-узел контроллера 890000. GPIO34 запрошен как вход, PullUp через PIN_MAP_CONFIGS_GROUP и pinctrl_get_select_default, IRQ EdgeBoth согласно ACPI. Прямые gpiod_set_config и gpiochip_generic_config вернули -ENOTSUPP: TLMM реализует group_set; нужен групповой pinctrl mapping. Оба неудачных подключения освободили GPIO до регистрации клиента.

OEM aw96103_0.bin установлен в /lib/firmware. Появился /sys/bus/iio/devices/iio:device0/name=aw96105_sensor. Штатный драйвер предоставил шесть raw-каналов (0..5); 0..4 включены, 5 отключён. В документации AW96105ADNR имеются регистры CH5, поэтому шестой файл сам по себе не ошибка. Точную роль шестого внутреннего канала и ревизию нужно уточнить.

Примеры выборок каналов 0..5:
- 96, 47, 306, 4194285, 4194208, 0
- 139, 22, 175, 4194295, 8, 0
- 242, 202, 4194272, 12, 4194273, 0
- 42, 282, 4194280, 55, 6, 0
- 125, 53, 171, 25, 17, 0

Меняющиеся значения подтверждают работу измерений; реакция на приближение тела и расположение электродов ещё не проверены. IRQ168 msmgpio34 aw96103_irq пока 0 событий, шторм не наблюдался. Звук tcl-audio и Weston active, taint=4096 как до теста.

Большие значения около 2^22 требуют проверки знака: код делит u32 data на 1024 до приведения к int. Datasheet описывает DIFF как разность и допускает отрицательные значения в алгоритмах; исправление чтения надо сверить с OEM-драйвером/форматом конкретной ревизии. Не интерпретировать raw как сантиметры.

Временное ограничение: реальный источник vcc не установлен. В пробе штатный regulator framework использует dummy regulator, физическое питание не переключается. Это наблюдение о текущем включённом питании, не описание постоянной схемы. Вспомогательный модуль без module_exit удерживает клиента и IRQ до перезагрузки; принудительно не выгружать. Автозагрузка датчика не установлена. Перед постоянным включением нужны корректное описание питания и жизненный цикл драйвера/firmware callback.

Windows qsarconfig7180.inf выбирает SUBSYS_27822600, NumberOfChannels=5, WlanAntCount=2. channel0=MODEM, channel1..4=WLAN, WlanAntMask=3. Это подтверждает назначение для радиомодуля/WLAN, но не расположение электродов.
