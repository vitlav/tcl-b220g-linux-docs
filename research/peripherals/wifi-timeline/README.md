# TCL: ранняя последовательность QRTR/QMI

Пункт `NEXT: Wi-Fi QMI timeline + auto reboot`. Основа wifi-services; ядро/DT/все firmware и библиотеки те же. Userspace qrtr-ns больше не запускается: сервер имён встроен в ядро, адрес1 штатный.

Перед загрузкой драйверов и непосредственно перед MPSS снимается qrtr-lookup. Параллельно старту — 30 снимков служб, remoteproc state/recovery и driver symlink PD mapper, с uptime и ограничением каждого lookup двумя секундами. Между снимками пауза2с. Это снимает ограничение предыдущего теста, где список был только после watchdog. Через30/55с снимаются ожидающие задачи ядра (sysrq-w). Логи qrtr-timeline.log автоматически копируются вместе с остальными. Удалено ошибочное cat /proc/net/qrtr из snapshot.

Одна попытка MPSS, recovery disabled. По окончании 90с наблюдения и работы сборщика — штатный отсчёт30с, финальное сохранение/sync/umount и reboot. Отмена cancel-reboot. Рабочие пункты сохранены. Это диагностический тест, не обещание исправления firmware. Подробное исследование и источники — ../wifi-research/README.md.

Проверены sh -n, структура CPIO, наличие новых скриптов и отсутствие запуска qrtr-ns, побайтовое совпадение firmware. Автоперезагрузка побайтово совпадает с уже проверенной wifi-services. SHA256 образов — SHA256SUMS.
