## Контроллер батареи по DSDT

ACPI I2C3 соответствует Linux i2c2 по MMIO 0x00888000, size 0x4000 и IRQ 0x27b = SPI603 + 32. Адрес EC 0x07, скорость 400000. В текущем Linux эта шина disabled; имеется только /dev/i2c-4 для HID. Сканирование I2C и запись регистров EC не выполнялись.

DSDT.dsl строки 46406–46617: GenericSerialBus IC3R читает AttribBytes(0x20) с offset 0, результат ECRB длиной 0x22 включает два служебных байта ACPI. Смещения полезной нагрузки ниже получены вычитанием двух байт; фактический ответ EC ещё не снят.

| Поле | Смещение ECRB | Смещение 32-байтных данных | Размер | Использование DSDT |
|---|---:|---:|---:|---|
| ELID | 0x03 | 0x01 | 1 | 0x80 означает закрытую крышку |
| ECWR | 0x04 | 0x02 | 1 | bit0 питание от адаптера, bit1 учитывается в присутствии батареи |
| B1DC | 0x08 | 0x06 | 2 | design capacity; DSDT также подставляет в last-full capacity |
| B1FV | 0x0a | 0x08 | 2 | расчётное напряжение в _BIF |
| B1FC | 0x0c | 0x0a | 2 | проверяется на ненулевое значение в _BIF |
| B1ST | 0x10 | 0x0e | 1 | младшие 3 бита в Battery State |
| B1CR | 0x11 | 0x0f | 2 | present rate вычисляется как B1CR*B1FV/10000 |
| B1RC | 0x13 | 0x11 | 2 | remaining capacity |
| B1VT | 0x15 | 0x13 | 2 | present voltage |
| BPCN | 0x17 | 0x15 | 1 | поле есть, но в показанных _BIF/_BST не используется |

Блок _BIF объявляет единицы mA/mAh, однако формулу rate нельзя физически трактовать без проверки сырых данных: сохранять отдельно raw и результат формулы DSDT.

Драйвер Acer Aspire1 из Linux v6.18 сохранён для сравнения. Он использует другие команды FG_STATIC=0x08, FG_DYNAMIC=0x07 и RAM_READ=0x20 с записью адреса; несовпадение протокола не позволяет назначать TCL compatible acer,aspire1-ec вслепую. Источник: https://github.com/torvalds/linux/blob/v6.18/drivers/platform/arm64/acer-aspire1-ec.c .

## UFS и полноценный DRM

Для UFS сохранить прежнюю таблицу PEP: L19A 2.96 В, L12A 1.8 В, L3C 1.2 В, L4A 0.88 В. Соответствие Linux supplies остаётся гипотезой, поддержанной аналогами. Включение одного status без питания/PHY/зависимостей — неполный тест. При последующем появлении LUN сначала только идентификация и чтение GPT, без монтирования Windows разделов для записи.

Для DRM нужны display clocks/MDSS/DSI и корректная цепочка мостика. По старому разбору EDPBridge.sys вероятен LT8911EXB, точный chip ID не считан; GPIO sequencing не отождествлять с Acer. Текущий efifb сохранять до отдельного теста. Строка fb0/modes U:1920x1080p-77 не заменяет физическое измерение частоты панели; EDID ранее дал около 60 Гц.

## Подготовка запуска EC

В BusyBox текущего образа присутствует i2ctransfer. Код Linux v6.18 i2c-core-acpi.c подтверждает, что AttribBytes использует пару I2C-сообщений: однобайтовую команду offset, затем чтение заданной длины. После проверки новой шины предполагаемая команда: `i2ctransfer -y 2 w1@0x07 0x00 r32` — без -f, после проверки принадлежности /dev/i2c-2 контроллеру 888000. Это чтение с предварительным выбором смещения, не запись настроек. Пока команда не выполнялась.

Сохранён decode-ec.py для разбора ровно 32 hex-байт в сырые поля и значения по формулам DSDT. Битовые/физические значения требуют проверки на аппаратных данных.

Новый пункт: TEST: battery EC bus + automatic Wi-Fi + SSH. По умолчанию остаётся tcl-online. EFI собран тем же Debian 2.12-9+deb13u2 с явными модулями, что и успешно загруженный образ.
